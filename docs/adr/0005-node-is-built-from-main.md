# Merging to main releases the Node's firmware

The Home Assistant ESPHome add-on builds the Node from `/config/esphome/geopro-202s.yaml`, which holds the tracked `addon/geopro-202s.yaml`. That file takes both the Node's settings (`node.yaml`, as a package) and the Component (`github://MatiasPuhakka/esphome-geopro202s@main`) from `main`. `geopro.yaml` includes the same `node.yaml` with the Component from the local checkout. We chose a `github://` source over copying `components/geopro_202s` into the add-on's `/config/esphome/components/` (#11), and a shared `node.yaml` over a hand-kept copy of `geopro.yaml` that CI never saw (#47). The cost is that `main` is the release: a merge there changes what the next install from the add-on builds and flashes.

The add-on follows `main` with `refresh: 0s` on both sources, so every build fetches the current `main` (#47). We chose that over pinning a commit or tag. With one user and no outside consumers, a pin buys reproducible builds, but every release would then mean a ref edit in the add-on, which only the owner can make in the Home Assistant UI. A rollback is a revert on `main` and a reinstall. The default `refresh: 1d` was ruled out because a build could miss a merge for a day.

ESPHome keeps the package and the Component in separate clones, and when a fetch fails it logs a warning and builds from the clone it has. One build can then pair a newer `node.yaml` with an older Component, or the reverse. A key the older Component doesn't know fails the build. Otherwise the flash check shows it: the Component revision entity names the commit the Component came from, and an entity the contract lacks fails the check. If outsiders start depending on the repo, pin both sources to a tag and revisit this.

`main` is protected: changes reach it only through pull requests (a GitHub ruleset with no bypass), and CI builds the Component and validates `geopro.yaml`, and so `node.yaml`, on each one. CI doesn't validate `addon/geopro-202s.yaml`, which fetches `main` rather than the pull request.
